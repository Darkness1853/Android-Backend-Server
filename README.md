# Теория

## Работа c сокетами Беркли (Sockets)

С помощью портов компьютер понимает, какие данные предназначены какой программе.

Сокет - это виртуальная конструкция из IP-адреса и номера порта. 

- Программист пишет в программе, что он хочет сделать новый сокет;
- Указывает для него IP-адрес, если это необходимо;
- Программа собирает это в виртуальную конструкцию, и получается сокет;
- после этого программист может отправлять данные просто в сокет и принимать их оттуда, а компьютер берёт на себя все вопросы по передаче данных.

### Основные функции

Для сервера:
```C
socket()  // Создать сокет
bind()    // Привязать к IP и порту
listen()  // Начать прослушивание
accept()  // Принять входящее соединение
```
Для клиента:
```C
socket()   // Создать сокет
connect()  // Подключиться к серверу
```
Для всех:
```C
send()     // Отправить данные
recv()     // Получить данные
close()    // Закрыть соединение
```

**Типы сокетов**
- **TCP**	Надёжный, потоковый, с установкой соединения
- **UDP**	Ненадёжный, датаграммный, без соединения
- **RAW**	Доступ к сырым пакетам (требует root)


У каждого процесса есть 3 стандартных дескриптора:

- 0 - **STDIN** (ввод)
- 1 - **STDOUT** (вывод)
- 2 - **STDERR** (ошибки)

## Библиотека Zero MQ (Android)

**ZeroMQ** - это высокоуровневая библиотека для асинхронного обмена сообщениями, которая работает поверх сокетов Беркли.

**Отличие от других сокетов**

- Асинхронные
- Автоматическое
- Автоматическое переподключение
- очередь сообщений

Простой шаблон "Запрос - Ответ"
```bash
Клиент (REQ)  -- запрос -->  Сервер (REP)
Клиент (REQ)  <-- ответ --  Сервер (REP)
```

## Проекция Меркатора

Это цилиндрическая проекция, которая сохраняет углы и формы объектов (равноугольная), но сильно искажает площади ближе к полюсам. Основные области использования - морская навигация, авиация, веб-карты и др.

Про стандарты:

EPSG:4326 - географическая система координат, основанная на системе параметров WGS84 (традиционно использует порядок широта - долгота, а EPSG 4326 - долгота - широта.). Единица измерения - градус;

EPSG:3857 - прямоугольная система координат, основанная на проекции **Меркатора**, построенной по системе параметров WGS84. Единица измерения – метр.

Преобразование GPS-координаты в позиции (X, Y) тайлов Меркатора.

**4 этапа:**
1. Преобразовать углы Latitude, Longitude в сферическую проекцию Меркатора (из EPSG:4326 в EPSG:3857) https://epsg.io/3857;
2. Преобразовать значения X, Y к отрезку [0 - 1], получая относительный квадрат;
3. Получить количество всей тайлов для текущего масштаба (zoom);
4. Умножаем X и Y на количество тайлов - получаем “имена” тайлов в формате zoom/x/y.

## Тайлы

Тайлы - это изображения небольшого размера (одинакового), являющиеся фрагментами большого изображения. 

### Правила наименований тайлов

1. Все тайлы имеют размер 256 × 256 пикселей формата PNG;
2. Каждое значение масштаба карты (zoom level) является директорией, каждый столбец также является директорией, в которой находятся изображения;
3. Ссылка (URL) на получения конкретного файла (*.png) формируется в формате: /zoom/x/y.png
- z - zoom
- x - номер столбца во всей матрице тайлов для текущего масштаба
- y - номер строки (или координата Y) в матрице.

### Получение тайлов из кода (curl)

- Получение координат тайла (X, Y) из GPS (Lat, Lon)
- Отправка запроса на тайл-сервер с помощью curl 
- Инициализация curl и настройка параметров
- Получение байтового массива

### Преобразование изображения в значения пикселей

.png состоит из двух основных частей:
- Подпись .png;
- Чанки (chunks) с данными.

Подпись PNG-файла состоит из 8 байт и представляет собой:
```bash
0x89 0x50 0x4e 0x47 0xd 0xa 0x1a 0xa
```

- **0x89** - Non-ASCII символ. Препятствует распознаванию PNG, как текстового файла.
- **0x50 0x4e 0x47** - PNG в ASCII записи.
- **0D 0A** - CRLF (Carriage-return, Line-feed), DOS-style перевод строки.
- **0x1a** - Останавливает вывод файла в DOS режиме (end-of-file), ограничивает изображение в текстовом виде.
- **0xa** - LF, Unix-style перевод строки.

**Чанки** - это блоки данных, из которых состоит файл. Каждый чанк состоит из 4 секций.

**Где:**
- Длина (4) — это числовое значение длины блока данных;
- Тип (4)- представляет собой 4 чувствительных к регистру ASCII-символа;
- Данные - само изображение;
- CRC (4)- контрольная сумма для проверки целостности.

# Принцип работы (потоки)

ПОТОК GUI (run_gui)
1. создание окна (1400x800)
2. Инициализация GLEW, ImGui, ImPlot
3. Подключение к PostgreSQL для загрузки точек на карту
4. Вызов init_map() и load_points_from_db()
5. glfwPollEvents() - обработка событий окна
6. ImGui::NewFrame() - начало нового кадра ImGui
7. Отрисовка вкладок (Location, Mobile Networks, Graphs, Log, Stats, Map)
- Location: отображение GPS данных, кнопка START/STOP SAVE JSON
- Mobile Networks: список всех сот (активные/соседние), их параметры (RSRP, RSRQ, SINR, PCI и др.)
- Graphs: графики RSRP/RSRQ/RSSI/SINR для активной соты 
- Log: лог сообщений от сервера
- Stats: статистика (количество сообщений, статус БД, запись в JSON и др.)
- Map: OSM карта с отображением точек из БД 
8. Отрисовка карты через draw_map():
9. Загрузка тайлов через TileManager
10. Отображение точек из PostgreSQL (map_points)
11. ImGui::Render() и ImGui_ImplOpenGL3_RenderDrawData() - рендер GUI

ПОТОК СЕРВЕРА (run_server)
1. Создание DBClient и подключение к PostgreSQL (порт 5435, БД visual_db)
2. Создание ZeroMQ и REP-сокета
3. socket.bind("tcp://*:5050") - ожидание подключений от Android клиента
4. Создание last_db_check для проверки БД
5. Для каждой сети парсинг/ извлечение: NetworkType, MCC, MNC, CellIdentity, PCI, TAC, RSRP, RSRQ, RSSI, SINR
6. Обновление истории графиков (per_pci_data)
7. Сохранение в таблицы: location (timestamp, send_id) → locations (координаты) → cells (параметры сетей)
8. Формирование JSON ответа {"status": "ok", "count": ..., "message": "Data received"}
9. socket.send() - отправка ответа клиенту

ПОТОК ЗАГРУЗЧИКА ТАЙЛОВ (TileManager::worker, внутренний поток)
1. При поступлении задачи (z, x, y):
2. Попытка загрузить тайл с диска (loadFromDisk())
- ЕСЛИ на диске нет, то запрос к https://tile.openstreetmap.org/zoom/x/y.png
